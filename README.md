# Splitly — мобильный клиент

Flutter-клиент к [splitly-backend](https://github.com/toniess/splitly-backend) для iOS и Android.
Экраны те же, что в [веб-клиенте](../splitly-web): группы, траты, балансы и план взаиморасчётов.

| Что | Выбор |
| --- | --- |
| Фреймворк | Flutter 3.47, Dart 3.13 |
| Сеть | `http` |
| Токены | `flutter_secure_storage` — Keychain / Keystore |
| Состояние | `StatefulWidget` + один `ChangeNotifier` для сессии, без библиотек |
| Тема | тёмная, палитра из `styles.css` веба |
| Языки | русский и английский, `gen-l10n` |

## Запуск

```bash
flutter pub get
flutter run                     # ходит в боевой бэкенд
```

Против локального бэкенда:

```bash
flutter run --dart-define=API_BASE=http://localhost:8080   # iOS-симулятор
flutter run --dart-define=API_BASE=http://10.0.2.2:8080    # Android-эмулятор
```

На Android-эмуляторе `localhost` указывает на сам эмулятор, а хост-машина доступна по `10.0.2.2`.
HTTP без TLS разрешён только для debug-сборки Android и для локальной сети на iOS. Прод работает по HTTPS.

## Экраны

- **Вход**: регистрация, логин и демо без регистрации.
- **Группы**: список, создание, вступление по коду, обновление свайпом вниз.
- **Группа**: код приглашения копируется тапом. Вкладки:
  - *Траты*: лента с курсорной пагинацией, страницы подгружаются при прокрутке.
  - *Балансы*: сальдо каждого участника.
  - *Расчёт*: минимальный план переводов и кнопка «Я отдал».
- **Новая трата**: поровну, по долям или точными суммами. При точных суммах
  форма подсказывает, сколько ещё осталось распределить.
- **Трата**: доли участников и удаление.
- **Меню аккаунта**: выход, политика конфиденциальности и запрос на удаление аккаунта.

## Устройство

```
lib/
  api/
    models.dart       типы ответов, повторяют record-ы бэкенда
    splitly_api.dart  интерфейс клиента, ApiError (RFC 7807), генерация UUID
    http_api.dart     настоящий клиент: токены, refresh, таймауты
    demo_api.dart     песочница в памяти с теми же расчётами, что на сервере
  l10n/               строки интерфейса: app_ru.arb (шаблон) и app_en.arb
  session.dart        кто вошёл и через какой клиент ходим
  support.dart        контактный адрес и ссылки на документы
  screens/            экраны
  ui/                 тема и общие виджеты
docs/                 политика конфиденциальности и инструкция по удалению аккаунта
store/                материалы и тексты для Google Play
```

Экраны работают с интерфейсом `SplitlyApi` и не знают, с какой реализацией имеют дело:
настоящей или демо. Поэтому в них нет веток `if (demo)`.

## Что стоит знать о клиенте

**Деньги — строки.** Суммы приходят и уходят строками, `double` нигде не используется.
Клиент складывает деньги только в демо-песочнице и в подсказке «осталось распределить»,
причём и там считает в копейках через `int`.

**Ключ идемпотентности живёт до успеха.** Веб-клиент генерирует `Idempotency-Key` на каждый
запрос, и повтор после таймаута там создал бы дубль. Здесь форма траты запоминает ключ
и момент траты до успешного ответа. Повторное «Сохранить» с той же формой уходит с тем же
ключом, и сервер узнаёт повтор. Если форму изменили, генерируется новый ключ.
Кнопка «Я отдал» устроена так же.

**Токен обновляется сам.** На `401` клиент обновляет пару по refresh-токену и повторяет
запрос один раз. Параллельные `401` ждут одного общего обновления: refresh-токен одноразовый,
и второе обновление сервер принял бы за кражу. Если refresh не прошёл, сессия сбрасывается
и открывается экран входа: открытые экраны снимаются со стека. На вход выкидывает только
отказ сервера в самом токене (400/401). Обрыв связи, 429 и 5xx сессию не сбрасывают.

**Keychain не переживает переустановку.** На iOS Keychain остаётся после удаления
приложения, и без защиты новая установка подхватила бы старую сессию. Поэтому рядом
в обычных настройках лежит флаг установки, а настройки удаляются вместе с приложением.
Если флага нет, это первый запуск, и старые токены стираются. На Android бэкап данных
приложения выключен: иначе флаг вернулся бы из облака без ключа Keystore, которым
зашифрованы токены.

**Язык выбирается по системе.** Если в списке языков системы есть русский или английский,
берётся первый из них. Иначе для языков СНГ (узбекский, казахский, украинский и так далее)
включается русский, для остальных — английский. Строки лежат в `lib/l10n/*.arb`, код
генерируется при `flutter pub get`. Тексты ошибок сервера показываются как есть: их язык
выбирает бэкенд.

**Удаление аккаунта — по запросу.** Эндпоинта удаления на бэкенде нет. Пункт меню
открывает письмо на contact@toniess.dev с уже заполненными почтой и ID аккаунта,
а удаляют вручную. Google Play это допускает; описание лежит в `docs/delete-account.md`.

## Тесты

```bash
flutter test
```

- `demo_api_test.dart`: инварианты денег из раздела 10 ТЗ на песочнице (остаток копеек,
  отказ EXACT, идемпотентность, сумма сальдо равна нулю, план обнуляет балансы).
- `http_api_test.dart`: единственный refresh при параллельных 401, разбор ошибок,
  заголовки и тело запроса на создание траты.
- `demo_flow_test.dart`: сквозной сценарий по экранам в демо-режиме.
- `session_expiry_test.dart`: сессия кончилась на экране группы — возврат на вход без падения.
- `token_store_test.dart`: токены прошлой установки стираются, при обычном перезапуске
  сессия сохраняется.
- `l10n_test.dart`: выбор языка, русские множественные числа, демо на английском.

**Сквозной сценарий** `integration_test/smoke_test.dart`: двое пользователей проходят всё
через настоящий бэкенд — регистрация, группа, вступление по коду, трата, балансы, «Я отдал».
Нужен запущенный эмулятор или устройство.

В CI (задача `e2e`) бэкенд собирается из `splitly-backend` и поднимается с чистой базой
через `.github/e2e/docker-compose.yml`, а сценарий идёт на Android-эмуляторе. Релиз по тегу
ждёт этой задачи.

Локально то же самое — рядом со своими контейнерами, на другом порту:

```bash
BACKEND_DIR=$PWD/../splitly E2E_PORT=18080 POSTGRES_PASSWORD=e2e JWT_SECRET=$(openssl rand -base64 48) \
  docker compose -p splitly-e2e -f .github/e2e/docker-compose.yml up -d --build --wait
flutter test integration_test/smoke_test.dart -d <устройство> --dart-define=API_BASE=http://10.0.2.2:18080
docker compose -p splitly-e2e -f .github/e2e/docker-compose.yml down
```

Без `API_BASE` сценарий пойдёт в прод и оставит там пользователей `splitly-smoke-*@example.com`,
удалить которых можно только вручную.

## Релиз

Тег `v*` запускает workflow `.github/workflows/ci.yml`: тесты, затем подписанные APK
(по одному на архитектуру) и AAB для Google Play. Всё это уходит в GitHub Release.

```bash
# поднять version в pubspec.yaml, затем:
git tag v1.0.1 && git push origin v1.0.1
```

Номер сборки (`versionCode`) в CI равен номеру прогона workflow, поэтому каждый
релиз получает новый.

**Ключ подписи** — upload-ключ Google Play. В репозитории его нет:

- локально он лежит в `~/.splitly/upload-keystore.jks`, пароль в `~/.splitly/key.properties`;
- в CI ключ берётся из секретов `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEYSTORE_PASSWORD`.

Без ключа debug-сборка работает, а release падает с понятной ошибкой: APK, подписанный
debug-ключом, Google Play не примет. Если ключ потерян, upload-ключ можно сбросить
через поддержку Play Console, потому что приложения подписывает сам Google (Play App
Signing). Всё равно держите копию `~/.splitly` в менеджере паролей.

Локальная сборка:

```bash
flutter build appbundle --release
flutter build apk --release --split-per-abi
```

**Иконка** рисуется скриптом `tool/icon.py` в `assets/icon`, а по размерам её раскладывает
`dart run flutter_launcher_icons`.

**Скриншоты для магазина** снимаются с демо-данных на обоих языках на запущенном
эмуляторе или симуляторе:

```bash
flutter drive --driver=test_driver/screenshots.dart \
  --target=integration_test/screenshots_test.dart -d <устройство>
```

Скриншоты сохраняются в `store/screenshots`. Google Play не принимает снимки, у которых
длинная сторона больше двух коротких, поэтому снимки с современных телефонов (19.5:9)
нужно расширить фоном до 2:1. Это делает `tool/store_assets.py`, он же рисует баннер. Тексты страницы и ответы на анкеты Play лежат в
`store/listing.md`.
